# Contributor boundaries: what never enters the public repo

The Scientific Resource Lab keeps a strict separation between **synthetic
public fixtures** and **real-world data or operational secrets**. This page
restates the exclusion list from the project plan for contributors.

## Never commit any of the following to the public repository

1. **Real research data**
   - Experimental measurements, survey responses, instrument traces, or lab
     notebooks.
   - Images, audio, video, or text corpora collected from people or the
     physical world.
   - Any CSV, Parquet, HDF5, or proprietary-format file that originated
     outside the synthetic generator.

2. **Credentials and secrets**
   - API keys, passwords, tokens, private keys, certificates, or session
     cookies.
   - Cloud provider credentials, database connection strings, or SSH keys.
   - GitHub personal access tokens, even example-like strings that match the
     `ghp_` shape.

3. **Absolute filesystem paths and host identifiers**
   - Paths under `/Users/`, `/home/`, `/Volumes/`, `C:\Users\`, or any other
     real home directory.
   - Machine hostnames, internal IP addresses, or container identifiers.
   - Personal directory names (operator usernames) or other operator-identifying names.

4. **Proprietary or licensed materials**
   - Third-party papers, preprints, datasets, or source code under a license
     incompatible with the public repository.
   - Trademarks, logos, or branding assets that are not ours to redistribute.

5. **Operational artifacts from private infrastructure**
   - Live telemetry, production logs, or backup dumps.
   - Internal run receipts, policy files, or governance documents that are not
     explicitly approved for public release.

6. **Non-deterministic or unbounded artifacts**
   - Random samples that cannot be reproduced from a documented seed and
     generator version.
   - Outputs whose size is not bounded by a documented limit (e.g., a fixture
     larger than 5 MiB without explicit approval).

## What is allowed in the public fixtures

Everything under `fixtures/public/` must be:

- **Fully synthetic**: produced by a standard-library generator with a fixed seed.
- **Deterministic**: the same generator version + seed produce byte-identical
  output on every run.
- **Self-contained**: a tutorial can use a fixture without contacting an
  external service or loading a private corpus.
- **CC0-1.0**: redistributable and modifiable without restriction.

## Why this matters

Public CI runs on GitHub Actions. Any committed real path, credential, or
proprietary file will eventually be printed, cached, or archived. The public
fixtures let the project demonstrate, test, and teach with zero risk of leaking
operational or personal information.

## If you are unsure

Ask before committing. A good rule of thumb: if the artifact was generated by
`fixtures/public/generate.py` from the documented seed, it is almost certainly
safe. If it came from your laptop, a cloud bucket, an instrument, or a human
subject, it is not.
